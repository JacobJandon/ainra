# Gates

A gate is a date this project committed to in public, with a bar and a registry that answers it. Publishing gates is
only worth anything if missing one is survivable and visible — so the rule here is narrow and absolute:

> **A gate is re-dated in the open, with a written reason, or it is not moved at all.**

Nothing in this repository can mark a gate met. `node tools/campaign.mjs gates` reads the live count from the source
named in the table and reports it; if the source cannot be read the count prints as `—`, never as zero.

## Why these two

**K1 asks whether anyone needs this.** Eight structured conversations with people who run agents that actually act
is a small number chosen to be answerable in two weeks, not a number chosen to be passable. If eight operators
cannot describe an agent-trust problem in their own words, the honest response is not more engineering.

**K4 asks whether anyone can check us.** A root that only its author can verify is not a root. Three distinct
parties, three separate challenges, three machines — and the bar is deliberately *execution-bound*: an attestation
counts only if the party produced verdicts on inputs they could not have precomputed. What that does and does not
prove is stated precisely in [`evidence/README.md`](../evidence/README.md).

Both are kill-gates in the original sense: a miss is information, and the response to a miss is a written decision,
not a quiet extension.

## How a gate closes

```sh
node tools/campaign.mjs gates                      # the live reading
node tools/campaign.mjs redate K1 <YYYY-MM-DD> --reason "..."   # the only way a date moves
```

Closing a gate is a maintainer's judgement recorded in `gates.json` (`status`, `result`) alongside the count that
justified it. The count itself always comes from the registry — for K4 that means a signature-checked artifact, and
for K1 a completed interview logged the same day it happened.

## What is *not* a gate

The three Definition-of-Done rows — verifiers, ceremony, soak — are not gates and are not tracked here. They are in
[`docs/DOD.md`](../docs/DOD.md) and rendered by `make genesis-status` from collected evidence. K4 and the verifier
row are related but not the same thing: K4 is a date by which we expected the row to move.
