# Gates

A gate is a **bar** this project committed to in public, with a registry that answers it. Publishing gates is only
worth anything if failing one is survivable and visible — so the rule here is narrow and absolute:

> **A gate is read in the open, with a written reason, or it is not read at all.**

There are **no dates**. A deadline is a promise about a calendar, and a promise about a calendar is the one kind of
claim nothing in this repository can verify — so a gate carries a bar and a source instead, and the honesty lives in
recording the reading rather than in hitting a date. Nothing here can mark a gate met by assertion:
`node tools/campaign.mjs gates` reads the live count from the source named below, and if that source cannot be read
the count prints as `—`, never as zero.

## Why these two

**K1 asks whether anyone needs this.** Eight structured conversations with people who run agents that actually act
is a small number, chosen to be answerable rather than to be passable. If eight operators cannot describe an
agent-trust problem in their own words, the honest response is not more engineering.

**K4 asks whether anyone can check us.** A root that only its author can verify is not a root. Three distinct
parties, three separate challenges, three machines — and the bar is deliberately *execution-bound*: an attestation
counts only if the party produced verdicts on inputs they could not have precomputed. What that does and does not
prove is stated precisely in [`evidence/README.md`](../evidence/README.md).

Both are kill-gates in the original sense: a reading is information, and the response to a bad one is a written
decision, not a quiet extension.

## How a gate is read

```sh
node tools/campaign.mjs gates                                    # the live reading
node tools/campaign.mjs record K1 <continuing|met|missed> --reason "..."
```

`record` refuses without a reason, stamps the count as it stood at that moment, and regenerates the table above. A
`met` or `missed` reading closes the gate; `continuing` leaves it open with the reading on the record.

## What is *not* a gate

The three Definition-of-Done rows — verifiers, ceremony, soak — are not gates and are not tracked here. They are in
[`docs/DOD.md`](../docs/DOD.md) and rendered by `make genesis-status` from collected evidence. K4 and the verifier
row are related but not the same thing: K4 is our own bar for whether independent verification is arriving at all.
