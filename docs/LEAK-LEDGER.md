# The leak ledger — what each party learns from one verification

Generated by `node tools/leak-ledger.mjs --write` (D-090); held to `evidence/leak-ledger.expected.json` by
`make leak-ledger`. Measured with the real SDK verifier on the fixture passport in
`packages/middleware/test/fixtures`, with every network entry point of the process recording calls. Verdict:
**valid**.

| Party | What it receives during one verification of a carried bundle |
|---|---|
| The verifier | every bundle field (19: `chain_keys`, `checkpoint`, `checkpoint_sig`, `claims`, `fresh_head`, `freshness`, `hop_proofs`, `inclusion_proof`, `issuer_sig`, `leaf_index`, `mandate_revocations`, `now`, `status_delegate_cert`, `status_issued_at`, `status_len`, `status_list`, `status_sig_ed25519`, `status_sig_mldsa65`, `status_uri`) and every claim (13: `authority`, `capabilities`, `cnf`, `exp`, `iss`, `keys`, `log`, `nbf`, `scope_ceiling`, `status`, `sub`, `tier`, `vct`). Nothing can be withheld: a bundle with one claim dropped is refused (`invalid:schema_violation`), because the registrar signed the claims whole. |
| The root | 0 requests — the root is not contacted (root-dark). |
| The registrar | 0 requests — the agent carries its registrar-signed status list, so the registrar learns only that its agent refreshed it, never who verified. |
| A status host or mirror | 0 requests in carried mode. A verifier that fetches a registrar's own list requests files that name the registrar (for example `registrar-07/status-list.json`, `registrar-07/status-list.jwt`), so the host learns whose agents it checks. D-091 publishes one file for the whole network, `network-status.json`, the same path whichever registrar is checked (names a registrar: no); a verifier that fetches should read that. |
| A network observer | 0 requests from the verifier, so nothing to observe. |

**Honest limit.** This covers what AINRA's own components receive. It cannot see what a CDN, a proxy or a network
logs beyond a request itself, and it measures one verification, not an agent's activity over time — the passport's
name is in every presentation, so an agent is linkable across verifiers by design (MTS §11).
