# v0.4.1 — the board at the release commit

`make preflight` from a **fresh clone** at `ee5772a`, per
[`RELEASING.md`](../../RELEASING.md) § *The one rule*. Run 2026-09-19.

**37 rows, ALL GREEN, no skips.** `ee5772a` is the commit the signed tag `v0.4.1` points at, so this board
attests the tagged tree itself rather than a parent of it — the one thing v0.4.0's board could not say.

CI on the release commit failed before this file existed, and it was right to: `changelog-board-check` saw
`CHANGELOG.md` claiming v0.4.1 with no board beside it. That is the rule working, not an obstacle to it. Nothing
was published in the interval.

Committing this file takes the board-proven release count from six to seven — the same trap v0.4.0 recorded, met
one release later. It is handled in the same commit: the five site surfaces that say "six" say "seven", and
`tools/status-consistency.mjs` now knows words past six, because at seven boards it compared every claim against
`undefined` and would have failed both spellings at once.
