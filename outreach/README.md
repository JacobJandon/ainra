# Outreach — the three people-powered steps to a founded root

The engineering is done and the machinery for the remaining steps is built and smoke-proven. What's left is not code —
it's **real people running real events** that outsiders can verify without trusting us. Each call below is a two-minute
read; each maps to a pending row on the [genesis checklist](../GENESIS-CHECKLIST.md) and shows up on the honest board
(`make genesis-status`).

| If you can… | Read | You light up (GENESIS-CHECKLIST) | Time |
|---|---|---|---|
| Verify software on your own machine | **[EXTERNAL-VERIFIER-CALL.md](EXTERNAL-VERIFIER-CALL.md)** | §3 — ≥3 external verifiers | ~10 min, once |
| Run a small always-on service | **[WITNESS-CALL.md](WITNESS-CALL.md)** | §4 — independent witnesses on separate infra | setup + always-on |
| Be trusted to hold a key share | **[CEREMONY-CUSTODIAN-BRIEF.md](CEREMONY-CUSTODIAN-BRIEF.md)** | §2 — recorded in-person ceremony | one recorded session + rehearsals |

*(The 14-day / 3-region soak — §5 — is machinery, not a recruit: whoever operates the live registrar runs
`kits/soak/DEPLOY.md` from three regions. It needs infrastructure, not a person to persuade.)*

## How these become the founding
1. **Verifiers** (§3) and **witnesses** (§4) can start today — they need no ceremony first; their evidence is collected
   and shown on the board as it arrives.
2. The **recorded ceremony** (§2) mints the real root; custodians rehearse until fluent, then run it once, on camera.
3. The **soak** (§5) runs continuously against the live root for 14 days across 3 regions.
4. When the board (`make genesis-status`) shows every row ✅ — each backed by a signature-checked artifact — the root is
   **founded**, and we publish the declaration with links to every proof.

## Principles (so no one is misled)
- **Nothing fake.** No event is "counted" without an artifact an outsider can independently check. A real zero beats an
  invented ten.
- **No hype, no third-party names.** These are plain asks with honest costs and honestly-scoped claims (see each doc,
  and `DECISIONS.md` D-024 for exactly what a verifier attestation does and does not prove).
- **You verify us, not the reverse.** Every role is structured so your contribution keeps the root honest *including
  against us* — that's the whole design.

Interested in any of the three? Each doc ends with how to reply.
