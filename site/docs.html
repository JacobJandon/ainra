DOCS / GET STARTED

Every check runs on your machine.

AINRA gives every AI agent a passport it can prove: who it is, who stands behind it, what it may do, and whether it is still trusted — verifiable offline, fail-closed, with the root switched off. These docs take you from zero to a verified passport in about a minute per page.

Everything below is real cryptography against a local testbed or the staging TEST-ROOT. The production root is born only at a recorded public ceremony — a pending, honestly-labeled milestone.

Get the reference

Clone the public repository. Every gate passes from a cold clone — that is the project's standing promise, re-proven by CI nightly and by the board in docs/releases/.

terminal
$ git clone https://github.com/JacobJandon/ainra && cd ainra
$ make verify        # the real verifier: a valid + a revoked credential, named reasons
$ make issue-first   # a local registrar + your first issued, verified passport

Prefer no checkout? The one-file reference CLI ships on the releases page and at Use the network — it runs with just node.

Verify in five lines

Point at a root-signed directory, verify the bundle, gate on the verdict. VALID proceeds; anything else returns a named reason — revoked, stale_status, alg_downgrade, … The decision stays yours.

typescript · @ainra/sdk
import { Verifier } from "@ainra/sdk";

const v = await Verifier.fromDirectory(dir);
const verdict = v.verify(bundle, now);
// → { status: "VALID" } — or a named reason
python · independent verifier
from ainra import Verifier

v = Verifier.from_directory(dir, root_ed, root_slh)
verdict = v.verify(bundle, now)
# → verdict.valid is True — or verdict.reason
Four independently written implementations — Rust core, TypeScript SDK, the reference CLI, and Python — agree on 745/745 conformance vectors, on verdict and reason. A disagreement would be a finding.

Gate a route

The middleware turns a verdict into an HTTP decision: invalid agents receive 403 plus an x-ainra-reason header, fail-closed.

node · @ainra/middleware
import { ainraGate, Verifier } from "@ainra/middleware";

app.use("/agent", ainraGate(verifier));

The CLI lifecycle

The whole lifecycle, locally, no server — a persistent registrar in a directory you own.

terminal
$ ainra init ./reg registrar-07
$ ainra issue ./reg --operator acme --lineage invoicing --version 1.0.0 --tier L2
$ ainra verify ./reg ainra:registrar-07:acme:invoicing@1.0.0
VALID
$ ainra revoke ./reg ainra:registrar-07:acme:invoicing@1.0.0 --reason key-compromise
$ ainra verify ./reg ainra:registrar-07:acme:invoicing@1.0.0
INVALID · revoked

Renewal is first-class: ainra renew reissues with logged continuity (prev_leaf) — identity is eternal, credentials are bounded.

For agents

An agent onboards itself from the machine-readable map — no account, no human in the loop:

  • /llms.txt — the capability map (what exists, what to fetch, honest status).
  • /skills.md — deterministic onboarding steps, executable exactly as written (CI replays them).
  • /.well-known/skills/index.json — installable skill index: npx skills add …

Prove your own implementation

AINRA certifies no one. The corpus and the runner are published; you point the runner at your implementation over a documented stdin/stdout contract, sign your own result, and anyone re-runs it to check. We don't certify implementations — we make certification unnecessary.

terminal
$ make conformance                    # the 3 in-repo impls, clean, same corpus hash
$ node tools/conformance/run.mjs --adapter ./my-verifier.sh
$ node tools/conformance/attest.mjs   # sign your result with YOUR key

The doctrine and roles: docs/conformance/PROGRAMME.md · the wire contract: tools/conformance/CONTRACT.md. A deliberately broken implementation is caught with named divergences — a conformance tool that cannot fail is theatre.

Verify a release

Releases are signed with an offline SSH key and — the stronger check — reproducible: rebuild the corpus byte-for-byte from the tag, no key needed.

terminal
$ ssh-keygen -Y verify -f allowed_signers -I release@ainra.org \
    -n file -s SHA256SUMS.sig < SHA256SUMS
Good "file" signature
$ sha256sum -c SHA256SUMS
$ make repro                          # byte-exact rebuild — trust the bytes, not us

The four-step guide with real pasted output lives in RELEASE-VERIFY.md.

Charter & the four rules

The whole standard is four sentences made mechanical:

  • Birth — no identity without a verified, accountable entity behind it. Ever.
  • Life — anyone can verify any passport, offline; verification never reports to anyone.
  • Death — only the issuer, the principal, or due process can revoke; every revocation is public, appealable, and honored everywhere in under a minute.
  • Neutrality — the root records facts. Never money, personal data, reputation, or judgment.

They distill six charter prohibitions, amendable only by supermajority in every member constituency after twelve months of public comment: issues no passports · computes no scores · processes no payments · holds no personal data · never gates L0 existence · features no registrar, ever.

Root keys are threshold-held (5-of-9) across five-plus jurisdictions and rotated in public ceremonies; independent witnesses cosign every log checkpoint; the whole root is forkable from public data — the right to leave is what keeps it worth staying with.

The plan

A member-governed, non-profit federation: issuers, attestors, verifiers, resolution & data providers, witnesses, and public-interest members each form a constituency in the assembly, which elects the board under charter constraints. Custodians and witnesses stand structurally apart from both.

Genesis, in order:

  • Ceremony rehearsed — DONE · FROST 5-of-9 across nine isolated processes, reproducible transcript (make ceremony-rehearsal-multi).
  • Recorded public ceremony — PENDING · sealed hardware on camera, air-gapped share generation, scripted T−30d → T+14d with a public abort playbook.
  • Independent verifiers — RECRUITING · three or more strangers verify fresh, un-precomputable challenges on their own machines and sign what they saw.
  • The soak — PENDING · fourteen days, three regions, signed reports; the founding declaration refuses to render without the evidence.

Economics: capped per-lineage-year fees at cents scale, flat accreditation, grants. Verification free, forever; at scale the cap falls toward archival cost.

The road: Prove (now — four implementations agree, a stranger's clone passes every gate) → Anchor (charter ratified, first public ceremony, live registrars) → Endure (pre-decided responses to pressure) → Disappear (verification as boring as the clock — plus a managed-migration clause: if a legitimately adopted successor emerges, the root's final duty is an orderly migration into it).

FAQ

Is AINRA a company? No — an international, member-governed, non-profit federation. It never competes with members, holds no equity, and is charter-bound out of issuing, scoring, payments, and personal data.

Why should anyone trust you? You shouldn't have to. The spec is public, the code runs in sixty seconds, keys will be split across jurisdictions, every action lands in witness-cosigned logs — and the standard is forkable, so if we go wrong, the ecosystem leaves with everything. Verify, don't trust applies to us first.

Nobody's on it yet — why join first? The alternative is pairwise trust-wiring at N² cost, forever. Verification is useful on day one with zero counterparties, and the founding table writes the rules everyone else inherits. The honest counter — LOGS SEALED: 0 — is the point: the first seats are authorship, not sponsorship.

What does it cost? Verifying: nothing, ever. Issuing: capped cents-scale per lineage-year through independent registrars.
