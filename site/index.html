What AINRA is made of

  1. The StandardDefines one passport, and how anyone checks it./0.1
  2. The verifierChecks a passport on your own machine — offline, fail-closed./0.2
  3. RegistrarsIssue passports under the same published rules, and log each one first./0.3
  4. RevocationSets one bit in a signed list; every verifier that checks refuses./0.4
  5. Running copiesGive every instance its own short-lived key./0.5

No one company runs the root. Registrars, custodians and witnesses share it, under one published rulebook.

What every check asks of an agent

Who it is

A lineage and a version — the agent itself, separate from any person behind it.

Who stands behind it

An operator, proven to an accredited registrar. The root never sees who.

What it may do

An authority class and a scope ceiling, signed. Running copies get narrower, shorter-lived keys.

Whether it is still trusted

A registrar-signed status, checked fresh. No fresh status, no entry: it fails closed.

Whether it was logged

Every passport is written to a public log before it is valid, so nothing is issued in secret.

Whether this request is its own

Each request is signed by the running copy's own key, bound to one method, host and path.
