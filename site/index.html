Why this exists

Soon, your AI will act for you.

Some already act alone: intrusion campaigns run, shutdowns evaded — all publicly reported. Every response presupposes what they lack: an identity that cannot be shed.

The problem

Anything can claim to be your agent.

Nobody can tell a real one from a fake.

The fix

A passport it can prove.

Who it is, what it may do — signed. Checked in milliseconds; a revocation is published in under a minute.

The control

Yours, not ours.

You set the limits, you pull the switch — we just make them provable.

The questions nobody can answer about an agent today

  1. Who created this agent?/Q1
  2. Who controls it now?/Q2
  3. What is it allowed to do?/Q3
  4. Has it been verified — or revoked?/Q4
  5. Is it pretending to be another?/Q5
  6. Can it legally act for a company?/Q6
  7. Can I safely delegate to it?/Q7

Tomorrow’s checks look like today’s — KYC for people, KYB for companies, KYA for agents: every acting AI carrying a scannable ID with a machine-readable zone.

What AINRA is made of

  1. The StandardDefines one passport, and how anyone checks it./0.1
  2. The verifierChecks a passport on your own machine — offline, fail-closed./0.2
  3. RegistrarsIssue passports under the same published rules, and log each one first./0.3
  4. RevocationSets one bit in a signed list; every verifier that checks refuses./0.4
  5. Running copiesGive every instance its own short-lived key./0.5
The shape of it

One root. Three rings.

Independent registrars issue, agents carry passports, verifiers decide — three rings, one neutral centre.

THE ROOT — AINRA

Keys, rules, revocation, logs. Everything chains up to it; every check stays local and fast.

RING 1 · INDEPENDENT REGISTRARS

Separate organizations issuing under identical published rules.

RING 2 · AGENTS

Each carries a passport chained to the root; its running copies get short-lived keys.

RING 3 · VERIFIERS

Anyone deciding whether to trust an agent — the check runs on their own machine, and each picks its own bar.

The root does four jobs and nothing else. It returns facts, never scores; every check runs on the verifier’s own machine, and the decision stays theirs.

No one company runs the root. Registrars, custodians and witnesses share it, under one published rulebook.

What every check asks of an agent

Who it is

A lineage and a version — the agent itself, separate from any person behind it.

Who stands behind it

An operator, proven to an accredited registrar. The root never sees who.

What it may do

An authority class and a scope ceiling, signed. Running copies get narrower, shorter-lived keys.

Whether it is still trusted

A registrar-signed status, checked fresh. No fresh status, no entry: it fails closed.

Whether it was logged

Every passport is written to a public log before it is valid, so nothing is issued in secret.

Whether this request is its own

Each request is signed by the running copy's own key, bound to one method, host and path.

Where the web is going

Web4: the web where software acts.

Each era of the web added one verb. The newest one is why agents need passports.

Pages you could read.

Posts, profiles, comments. Anyone could publish.

Keys and wallets. What you held was yours.

Web4 · now
READWRITEOWNACT

Agents act for you while you are elsewhere. They talk to other agents, sign, buy and trade.

An act needs an actor. Before a shop, an API or another agent lets yours in, it needs four answers: who it is, who stands behind it, what it may do, and whether it is still trusted. An AINRA passport carries all four, and anyone can check them offline.

Internet freedom

Proof for the people under pressure — without being watched.

Newsrooms, human-rights groups and activists face impersonation and surveillance first. AINRA gives them certainty about the software they deal with, and the check itself tells no one anything.

/01

A real tool, not a decoy.

Check that an agent belongs to the organisation it names, and not to an impersonator or a spoofed bot: the passport carries its operator, proven to an accredited registrar.

/02

A check that calls no one.

Signatures and revocation are checked on the verifier’s own machine, from public files. No request goes to us or anyone during a check, so there is no log of who checked whom.

/03

A seized key, switched off.

If a device or an agent’s key is taken, one bit set in the signed status list (an IETF Token Status List) makes every verifier that checks refuse it — within its freshness class: 30 seconds at F1, five minutes by default.

/04

No single owner, two signatures.

Every passport is signed twice, Ed25519 and ML-DSA-65, so it holds even if one scheme falls — including to a future quantum computer. The root is built to be held 5-of-9 by independent custodians; today it is pre-ceremony, with no witnesses yet.
