What changed, and why it matters.

Releases, rules, security and the network. There are few entries here on purpose: each one is written by hand, says what happened in plain words, including what we got wrong, and links to its proof.

November 2026

13 November 2026NetworkMajor

The test network has new keys, and a page here was wrong about four passports

The record on this site is a copy of what our test network serves. For four passports the copy and the registrar disagreed: the registrar said they were no longer in its log, and the page here showed them as VALID. A review found it on 12 November. Our own checks were green that day, because they compared the copy with the server that hands it out, and never asked the registrars.

Behind it was something an outside review had already named on 7 November. The test registrars' keys were worked out from their public names, so anyone could work them out too.

On 13 November we replaced the keys with ones from the operating system and started the test network's passports again: eight of them, two revoked. The directory that names the new keys is epoch 2. Epoch 1 stays in the history, because a record that drops its own past is not a record. If you mirror the directory you will see the new epoch arrive under the same test root.

A new check now asks every registrar about every passport in the record, every morning. This is a test network under a test root, and no real key was involved. We are telling it anyway, because a page that says VALID is read as a claim.

13 November 2026ReleaseMajor

0.8.1: a security release. Please upgrade the gate

If you use @ainra/middleware, upgrade to 0.8.1. A crafted passport name could make every earlier version throw while answering, and stop a server that did not catch the error. Nothing was ever let in that should have been refused.

The same release carries two smaller fixes of the same family, both told below, and one thing that is new: the pilot can now sit beside one of your routes and only watch. It refuses nothing, signs nothing, and tells you what share of your traffic carries a signature, what a gate would have decided, and how long the check takes on your own machine.

The other packages have no change in behaviour and move with the version.

13 November 2026SecurityMajor

Our command-line tools printed a stranger's text as written

A passport names itself, and both of our command-line tools printed that name exactly as it was sent. A name with a line break in it could write a line of its own on your screen, reading ALLOW or VALID, right beside the real answer.

The real answer was never wrong: the verdict, the exit code and the machine-readable line were correct every time. But a person reading the screen, or a log that keeps the first word of each line, could have been misled.

We did not find this with a test. We found it by reading another project's report of the same fault in its own verifier, and then trying ours. Both tools now print anything a presenter wrote with its unusual characters escaped. If you downloaded the reference CLI, replace 0.3.4 with 0.3.5.

12 November 2026Security

An advisory in a test tool, and a red light nobody saw for a day

A public advisory was filed against a small library our tests use. Nothing you run from us links it, and no published file changed when we updated it.

The part worth telling is our own slip. Our weekly check went red on 11 November and nobody looked until the next day, and by then we had pushed twice. Since then the same check runs before every push, and two more of our own records are checked on every change instead of only on our machines.

The advisory, scopedIncident INC-2026-009

12 November 2026SecurityMajor

A crafted passport name could stop a gate

The gate in @ainra/middleware writes its verdict into a response header. A passport name containing a character no header can carry made the server throw while writing it: a refusal turned into an error page, and a server that did not catch the error stopped.

Nothing was ever wrongly let in. This is about staying up, not about who gets through.

It is fixed in @ainra/middleware 0.8.1, with a test that fails on the old code. Every earlier version is affected, so please upgrade. For a day the fix was public and the patched package was not; a fix and its release belong in one step, and next time they will be.

12 November 2026Network

Another agent-identity project launched with wide backing

On 10 November a project with a public log, status tokens and an offline verifier launched under a large open-source foundation, with well-known companies behind it. That is good news for the idea we share: an agent should be able to prove who it is.

We read its published documents again on 12 November and brought our landscape page up to date. Where we differ, and where we do not yet do better, is written there with a source for every line.

7 November 2026ReleaseMajor

0.8.0: an outside review, and passports that can move

The first independent adversarial review of the code found real faults in the reference registrar, and this release fixes all of them. The worst: a demonstration door that could revoke, renew or issue under a real passport's name, and a server that one idle connection could stop.

Two things are new. A passport's lineage can move to another registrar, and it can change owner. Each move is signed by the operator, stays public for five days, and can be stopped by the old key during that time.

A gate can also now refuse a registrar, a lineage or a single name by its own policy, without waiting for anyone else to act.

6 November 2026RulesMajor

How fast we must tell you when something goes wrong

We wrote down deadlines for ourselves and made them public. The most serious kind of incident gets an entry in the public log within three days and a fix or a way around it within fourteen. A lesser one gets seven days and thirty.

A late entry has to say why it was late. The check that holds us to this turns red on the day a deadline passes, so it cannot be satisfied by not looking.

The rulesThe public incident log

4 November 2026RulesMajor

We corrected the Standard where it said more than the code does

We read our own Standard against our own code and found places where the text promised more than was built. It described the passport as a format with selective disclosure; in fact every claim in a passport is shown. It said the person behind an agent was proven without revealing them; no such proof exists in the code, where a registrar checks evidence and the passport carries a fingerprint of it. It said the depth of delegation was capped; it is not.

We changed the text to match the code, not the code to match the text, and recorded each change in the amendment log. A standard that describes what was not built is a promise with nothing behind it.

4 November 2026Release

0.7.0: every check shows it can fail

A check that cannot fail proves nothing. In this release each gate has a planted fault that it must catch, and that list runs on every change.

Also in it: a witness that someone outside the project can actually run, and a verifier that never goes back to an older list of registrars once it has seen a newer one.

The signed release

2 November 2026Release

0.6.0: links for a second kind of key

A link gives an agent's existing key an accountable owner and a way to be revoked. This release adds links for the kind of key most wallets use, and makes a cut-off record of a gate's decisions visible once its latest entry is logged.

The signed release

October 2026

29 October 2026ReleaseMajor

0.5.0: revocation for keys agents already hold

Most agents already sign their requests with a key, and that key can only be revoked inside the system that issued it. A link is a registrar's signed, logged statement that such a key acts for one passport, with one bit in a status list that anyone can check offline.

The same release publishes that status list in the standard format other libraries already read, and lets a gate keep a signed, chained record of every decision it took.

It also owns two faults. Our reference registrar forgot revocations when it restarted, so a revoked passport verified again; no release carried it, and it is fixed with a test that kills and restarts the real program. And a library we depend on leaked timing while signing; no production key existed.
